# Native early pan release proposal

This is one TMP-only candidate against the copied combined ROOT source after R8 diagonal adoption. No ROOT edits, campaign, complete match, acceptance re-score or timing-profile change ran. Source bindings are in source-hashes.json and the full original copy manifest in base-hashes.json. Every native run used CPU 3 and nice 19.

Actual client `main.js` keyup removes `e.code` from the held Set. `camera.update` then integrates only the still-held directions. A player can release a pan before arriving at its earlier goal. The previous executor preserved every complete planned hold, which can move a watched selected victim outside the camera and require a return trip after an emergency.

The candidate adds an optional immutable actual-public-event context to interruptHands. The commander passes only its already selected real emergency. The motor layer verifies that complete descriptor against its delivered view.events before changing a pan. Unpressed original or secondary preparation can cancel without pretending a key was pressed. Each already pressed key gets an actual early release clock. The release uses the unchanged sampled key motor and sampled existing reaction/off-screen range, anchored to the real creation tick with the existing four-tick floor. Camera movement continues through that paid reaction and release preparation. Release changes only the executed holding duration, retains original preparation, planned up tick and original purpose, and counts the original pressed key once. It adds no keyup APM input, matching the client recorder. Existing selection, issuing locality, budgets, command gate and non-pan held-gesture rules remain.

Physical metadata `panRelease` contains requestedTick, releaseStartTick, releasedTick, releaseMotorTicks, plannedUpTick, keyDownTick and the full actual cause. action.duration and panHold represent the actually executed interval; plannedPanHold retains the abandoned plan. Original event/response links are not relabeled. A camera release cannot acknowledge a new watched emergency just because that emergency caused it.

The optional v1-compatible native capture addition is prospective panGestureVersion 3. A separate sealed interruption request records original startId, request registration tick, release metadata and the identical actual delivered cause. The original start retains its planned motor/up clock. Completion validates the actual shortened interval against that sealed request, original paid preparation, positive release motor, cause floor and actual component-by-component camera reconstruction. Cardinal and concurrent partial releases remain censored if the original alert marker stays outside. Historical streams are not modified or re-scored. The separate alert-v2 worker may use this request proof or conservatively retain unknown/censored early-release coverage; input metadata alone is insufficient.

The declared useful scene has real default think, viewFor/perceive, native timed inputs and command receipts. A rifle first pays selection, G, move placement, stance and useful grenade gestures. Its selection is retained when the commander starts a real two-key camera trip to a remote objective. The fixture author supplies a 55% hit at the first actual held-pan phase where that already selected actor is still on screen. This trigger was declared before the compared runs and never changes planner/attention/selection state. Both runs create the same screen-damage event at tick 120 and have identical prior inputs. The full-hold baseline completes the old pan at 141/144, returns at 172/174, and accepts retreat at 183 (3.15 seconds). The candidate pays reaction and a three-tick release motor, records both real keyups at 128, then pays normal R and accepts retreat at 132 (0.60 seconds). The actor stays currently on screen without a return camera. Capture on/off yields exactly equal complete native inputs, commands, events and public frames.

This is not a replay of archived V21 damage 538. It is a small authored proof of the same concrete held-pan round-trip behavior. Its 0.60-second command response does not pass the Hard 0.30 to 0.45 first-input target. There is no gate-pass, pooled median, overall APM or performance claim.

Eight focused native gesture controls preserve cardinal and concurrent motion, pending first and second preparation, after-release requests, wrong and newly arriving causes, and an exhausted budget. Every executed frame matches the actual imported client camera rig and its keyup semantics. Already released inputs are not rewritten; wrong or altered descriptors cannot invent early keyups; a new cue does not replace an already scheduled release cause. Existing full-target gestures without an actual emergency context still finish normally. Public-alert controls retain real partial-arrival censors, canceled/retargeted/wrong-purpose negatives and collector on/off state parity.

Original response assertions migrate intentionally from the abandoned full planned hold to a real early keyup with positive motor, exact executed clock, original planned-up record and the same immutable actual cause. The existing response scene still moves its victim off screen before even the earlier release and therefore still must pay a later return before a currently visible actor receives retreat. Those original locality, return-camera, post-arrival deliberation and immutable-creation assertions remain. The complete hands and diagonal suites pass unchanged.

Development qualification: an initial 40% hit left the rifle at 60%, above the actual Hard 50% manual retreat threshold, and correctly produced no retreat. It was an authored setup negative, not a source failure. The useful declared fixture uses 45% health, above the engine's 35% automatic-retreat threshold. Initial native wrappers used the wrong lab engine property and omitted the baseline keys dependency; both failed before producing gameplay evidence. The existing response fixture initially rejected the deliberate early-release behavior (92 versus old planned 96) and was migrated to truthful executed/planned clocks. No favorable seed, profile, cap, reaction threshold or population was substituted.

Candidate source scope: shared/ai-hands.js, one actual-emergency argument in shared/ai-commander.js, optional capture compatibility in tools/ai-public-alert-response.mjs, the two related existing fixtures and new portable test-engine-ai-pan-release.js. ROOT owns registration, final capture-policy integration and full-source release checks. No changes to planner, perception, simulation, RNG, camera/keyboard client or lab runtime.
